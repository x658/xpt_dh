グローバルな開発者プラットフォームを構築する際、国際化（i18n）は単なるクライアント側のテキスト置換だけでは不十分です。クライアントサイド JavaScript だけで言語を切り替えると、ハイドレーション時の表示ちらつきや LCP（最大視覚コンテンツの表示時間）の悪化を招くだけでなく、検索エンジンのクローラーが各言語のページを正しくインデックスできなくなります。

本ガイドでは、**Next.js 16 App Router + `next-intl` + React Server Components (RSC) MDX** を組み合わせ、静的プリレンダリングと高速なエッジ配信を実現する多言語アーキテクチャを解説します。

---

## 1. ロケールルーティングと URL プレフィックス戦略

多言語サイトの URL 構造にはサブドメイン方式（`ja.example.com`）とサブパス方式（`example.com/ja`）がありますが、ドメイン評価（Domain Authority）の集約と証明書管理のシンプルさから、**`as-needed` プレフィックスを用いたサブパス方式**が最も推奨されます：

* **デフォルト言語（`en`）**：ルートパス（`/`、`/tools`、`/blog`）で直接配信。
* **追加言語（`zh`、`ja`）**：明示的なロケールプレフィックス（`/zh/tools`、`/ja/blog`）で配信。

```typescript
// i18n/routing.ts
import { defineRouting } from 'next-intl/routing';
import { createNavigation } from 'next-intl/navigation';

export const LOCALES = ['en', 'zh', 'ja'] as const;
export type Locale = (typeof LOCALES)[number];
export const DEFAULT_LOCALE: Locale = 'en';

export const routing = defineRouting({
  locales: LOCALES,
  defaultLocale: DEFAULT_LOCALE,
  localePrefix: 'as-needed',
  localeDetection: false, // 重要：検索クローラーへの強制 307 リダイレクトを防止
});

export const { Link, redirect, usePathname, useRouter } =
  createNavigation(routing);
```

> **SEO 上の重要ポイント**：`localeDetection: false` に設定することで、主に米国 IP（`Accept-Language: en-US`）からクロールする Googlebot が `/ja/...` や `/zh/...` へアクセスした際に、ミドルウェアによって強制的に英語ページへリダイレクトされる事故を防ぎます。

## 2. `generateStaticParams` による全言語の静的生成

エッジ CDN で 50ms 未満の TTFB（最初の 1 バイトが到着するまでの時間）を実現するため、動的セグメント `[locale]` および `[slug]` はビルド時にすべて静的プリレンダリングします。

```typescript
// app/[locale]/blog/[slug]/page.tsx
import { LOCALES, Locale } from '@/i18n/routing';
import { getPosts } from '@/lib/getBlogs';
import { setRequestLocale } from 'next-intl/server';

export async function generateStaticParams() {
  const allParams: { locale: Locale; slug: string }[] = [];

  for (const locale of LOCALES) {
    const { posts } = await getPosts(locale);
    for (const post of posts) {
      allParams.push({
        locale,
        slug: post.slug.replace(/^\//, ''),
      });
    }
  }

  return allParams;
}
```

すべての `(locale, slug)` の組み合わせをビルド時に列挙することで、ランタイムでのサーバー計算をゼロにし、静的 HTML として配信できます。

## 3. 双方向 `hreflang` と Canonical メタデータの実装

多言語 SEO において、各言語ページ間の関係性を検索エンジンに正しく伝えるには、相互参照する `hreflang` タグと自己参照 `canonical` URL が不可欠です：

```typescript
// lib/metadata.ts
export function buildAlternates(siteUrl: string, locale: string, defaultLocale: string, canonicalPath: string) {
  const cleanPath = canonicalPath === '/' ? '' : canonicalPath;
  const canonical = `${siteUrl}${locale === defaultLocale ? '' : `/${locale}`}${cleanPath}`;

  const languages: Record<string, string> = {};
  for (const lang of ['en', 'zh', 'ja']) {
    languages[lang] = `${siteUrl}${lang === defaultLocale ? '' : `/${lang}`}${cleanPath}`;
  }
  languages['x-default'] = `${siteUrl}${cleanPath}`;

  return { canonical, languages };
}
```

### チェックリスト：
1. **相互リンクの整合性**：`/blog/guide` が `/ja/blog/guide` を指している場合、`/ja/blog/guide` からも必ず `/blog/guide` を指すこと。
2. **絶対 URL の使用**：相対パスではなく `https://` から始まる完全な URL を出力すること。
3. **`robots.txt` で `/_next/` をブロックしないこと**：Google の Web Rendering Service が CSS や JavaScript バンドルを読み込めるようにしておくこと。

## 4. サーバーコンポーネント（RSC）での MDX コンパイル

クライアントに重い Markdown パーサーを送信する代わりに、`next-mdx-remote-client/rsc` を用いてサーバー側（ビルド時）に MDX をコンパイルします：

```tsx
import { MDXRemote } from 'next-mdx-remote-client/rsc';
import remarkGfm from 'remark-gfm';
import MDXComponents from '@/components/mdx/MDXComponents';

export async function ServerArticleBody({ source }: { source: string }) {
  return (
    <article className="prose prose-slate dark:prose-invert max-w-none">
      <MDXRemote
        source={source}
        components={MDXComponents}
        options={{
          parseFrontmatter: true,
          mdxOptions: {
            remarkPlugins: [remarkGfm],
          },
        }}
      />
    </article>
  );
}
```

これにより、クライアント側の JavaScript バンドルサイズを最小限に抑えながら、コードハイライトやインタラクティブコンポーネントを柔軟に組み込むことができます。

---

## 5. まとめ

`as-needed` サブパスルーティング、クローラーを妨げないロケール設定、`generateStaticParams` による完全静的生成、そして双方向 `hreflang` メタデータを組み合わせることで、Core Web Vitals とグローバル SEO の双方で最高水準のパフォーマンスを実現できます。
