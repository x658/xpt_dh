Transferring text snippets, API tokens, configuration files, and quick screenshots between laptops, workstations, and mobile devices is an essential daily workflow for developers. Yet, existing cloud clipboards and file-sharing utilities often suffer from severe trade-offs:

1. **Third-Party Privacy Risks**: Proprietary clipboard sync tools frequently log sensitive tokens, credentials, and code snippets on remote black-box infrastructure.
2. **Server Infrastructure Overheads**: Deploying dedicated Docker containers or VPS instances (Redis, Node.js, Nginx) incurs persistent monthly costs ($5–$20/mo) and continuous security patching.
3. **Public Exposure Vulnerabilities**: Open anonymous clipboards quickly degrade into targets for automated abuse, spam, and illicit file hosting.

To resolve these friction points, we built and open-sourced **XPT-Clip**—a production-grade, multi-user serverless cloud clipboard and file drop system built natively on **Cloudflare Workers** and **Cloudflare D1 (Edge SQLite)**. 

You can test the live service at [clip.xptdev.com](https://clip.xptdev.com) or inspect the repository on [GitHub (x658/xpt-clip)](https://github.com/x658/xpt-clip).

## Architectural Blueprint

The architecture is designed around a zero-server edge philosophy:

```
[ Developer Browser / Mobile Client ]
               │  (HTTPS / REST API + Single Page App)
               ▼
   [ Cloudflare Global Edge Network ]
   (330+ Cities Anycast Routing, Sub-50ms Latency)
               │
               ▼
    [ Cloudflare Worker (V8 Engine) ]
    ├── JWT Authentication & Multi-Tenant Isolation
    ├── Dynamic Disposable Invite Code Validator
    ├── Fast Base64 File Processor (Up to 2MB)
    └── Granular TTL Expiration Engine (10m to 7d)
               │
               ▼
  [ Cloudflare D1 Edge Database (SQLite) ]
  ├── `users` & `invites` (Role-based access)
  └── `clips` (Indexed by user_id & public share_id)
```

### Why Cloudflare Workers + D1?
* **Zero Cold Starts**: The V8 isolate architecture initializes in under 5 milliseconds globally.
* **Serverless Edge Storage**: Cloudflare D1 delivers relational ACID guarantees with SQLite simplicity right at the edge.
* **100% Free Tier Viability**: 100,000 requests/day, 5,000,000 D1 read rows/day, and zero egress transfer fees make ongoing operational costs strictly $0.00.

## Core Security & Multi-Tenancy Design

A primary flaw of open clipboard tools is that opening registration leads to abuse, while closing it prevents team collaboration. XPT-Clip solves this with a **Two-Tier Dynamic Invite Engine**:

### 1. Zero-Config Super Admin Initialization
On the very first cold run, the database has zero registered users. The first person to visit the platform can claim the **Super Admin** role with a master password. Immediately afterward, registration locks down completely.

### 2. Single-Use Disposable Invite Codes
New users cannot sign up freely. Instead, the Super Admin generates single-use disposable invite codes directly from their dashboard:
```sql
CREATE TABLE IF NOT EXISTS invites (
  id TEXT PRIMARY KEY,
  code TEXT UNIQUE NOT NULL,
  created_by TEXT NOT NULL,
  role TEXT DEFAULT 'user',
  is_used INTEGER DEFAULT 0,
  used_by TEXT,
  created_at INTEGER NOT NULL,
  used_at INTEGER
);
```

When an invite code is submitted during registration, the Worker executes an atomic verification transaction:
1. Confirms the invite code exists and `is_used = 0`.
2. Hashes the new user's password using salted SHA-256 with an edge secret pepper.
3. Inserts the new tenant into `users` and marks `is_used = 1` simultaneously.

## Technical Highlights & Features

### 1. Multi-Tenant Data Isolation
Every persistent clip is tagged with the user's cryptographically signed `user_id`. Normal queries only return records owned by the authenticated caller:
```sql
SELECT id, title, content, is_file, file_name, file_size, expires_at, created_at 
FROM clips 
WHERE user_id = ? 
ORDER BY created_at DESC;
```

### 2. Base64 Fast File Drop
XPT-Clip supports seamless drag-and-drop file transfers (JSON schemas, environment files, logs, screenshots, patches) up to 2MB. Files are encoded directly as high-throughput Base64 data URIs and stored inside edge SQLite records, completely eliminating the need for expensive external object buckets (S3/R2) for lightweight assets.

### 3. Granular Self-Destruct Timers
Clips default to a **10-minute auto-expiry window**, drastically reducing edge storage footprint. Users can also customize retention policies:
* 10 Minutes (Default — optimal for sensitive keys & one-time passwords)
* 1 Hour / 1 Day / 7 Days
* Permanent (for recurring snippets and documentation)

Expired clips are automatically filtered out during retrieval queries, ensuring self-cleansing operation.

### 4. Ephemeral Secret Links with View Limits
When a user needs to share a snippet or file with an external contractor or friend without giving them an account, they can generate a **Secret Public Link** with customizable view thresholds (e.g., destructs after 1 view or 5 views).

## Open Source & Deploying Your Own

The entire system is licensed under the permissive **MIT License** and can be deployed to your own Cloudflare account in under 3 minutes:

```bash
# Clone the repository
git clone https://github.com/x658/xpt-clip.git
cd xpt-clip

# Create your D1 edge database
npx wrangler d1 create clip-db

# Execute the schema initialization
npx wrangler d1 execute clip-db --remote --file=./schema.sql

# Deploy to Cloudflare Workers
npx wrangler deploy
```
