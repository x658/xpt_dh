Transferring text snippets, API tokens, configuration files, and quick screenshots between laptops, workstations, and mobile devices is an essential daily workflow for developers. Yet, existing cloud clipboards and file-sharing utilities often suffer from severe trade-offs:

1. **Third-Party Privacy Risks**: Proprietary clipboard sync tools frequently log sensitive tokens, credentials, and code snippets on remote black-box infrastructure.
2. **Server Infrastructure Overheads**: Deploying dedicated Docker containers or VPS instances (Redis, Node.js, Nginx) incurs persistent monthly costs ($5–$20/mo) and continuous security patching.
3. **The Serverless File Limit Bottleneck**: Traditional serverless architectures (like Cloudflare Workers) strictly constrain request payload sizes (100MB max payload, 128MB RAM, 10ms CPU limit), making large asset transfers historically impossible on free-tier edge computing.
4. **Public Exposure & Spam Abuse**: Open anonymous pastebins quickly degrade into targets for automated abuse, spam, and illicit file hosting.

To solve all of these friction points, we designed and open-sourced **XPT-Clip**—a production-grade, multi-tenant serverless cloud clipboard and file drop system built natively on **Cloudflare Workers** and **Cloudflare D1 (Edge SQLite)**, engineered with a **Smart Dual-Engine architecture** capable of handling transfers from small snippets up to **1GB heavy assets** at strictly **$0.00 operating cost**.

You can test the live service at [clip.xptdev.com](https://clip.xptdev.com) or inspect the repository on [GitHub (x658/xpt-clip)](https://github.com/x658/xpt-clip).

## Architectural Blueprint

The architecture follows a zero-server edge philosophy, decoupling control-plane metadata transactions from high-throughput binary streaming:

```
[ Developer Browser / Mobile Client ]
         │
         ├── (≤ 2MB Payload / Text Clips / Auth) ───► [ Cloudflare Edge Workers ]
         │                                                    │
         │                                                    ▼
         │                                      [ Cloudflare D1 (Edge SQLite) ]
         │                                      ├── Users & Invite Verification
         │                                      ├── Base64 Inline Blobs (≤ 2MB)
         │                                      └── Metadata & Share Access Tokens
         │
         └── (> 2MB to 1GB Direct Stream) ──────────► [ High-Speed Edge Relays ]
                                                              ▲
                                                              │ (Streaming Pipe)
 [ Downloader Client ] ◄── (Edge Reverse Stream) ─── [ Cloudflare Worker Proxy ]
```

### Why This Architecture Excels:
* **Zero Cold Starts**: The V8 isolate architecture initializes in under 5 milliseconds globally.
* **Smart Dual-Engine Storage**: Small files stay private inside edge SQLite, while multi-hundred-megabyte files bypass serverless memory bottlenecks completely.
* **100% Free Tier Viability**: 100,000 requests/day, 5,000,000 D1 read rows/day, and zero egress transfer fees make ongoing operational costs strictly **$0.00** without binding a credit card.

## The 1GB Smart Dual-Engine Breakthrough

The core engineering hurdle with edge computing is payload handling. Cloudflare Workers impose a strict 100MB body cap and memory ceilings on the free tier, and D1 SQLite tables degrade in performance when storing massive multi-megabyte binary blobs.

XPT-Clip solves this with a **transparent client-side dual-engine router**:

```
                              [ File Input Drop ]
                                       │
                         Is file size <= 2MB?
                        /                    \
                     [YES]                   [NO]
                      │                       │
      [ Tier 1: Local Edge Engine ]   [ Tier 2: Relay Stream Engine ]
      • Read as Base64 Data URI       • Register Metadata in D1
      • Direct insert into D1 DB      • Client Direct Stream Upload
      • Zero external dependency      • Supports up to 1GB Archives / ISOs
```

### 1. Tier 1: Local Edge Engine (≤ 2MB)
Lightweight snippets, logs, `.env` configs, scripts, and screenshots are encoded into compact Base64 strings and stored directly within Cloudflare D1. They benefit from instant edge retrieval, strict cryptographic access isolation, and zero third-party dependencies.

### 2. Tier 2: High-Speed Streaming Engine (> 2MB up to 1GB)
When a user drops an archive, software binary, or multi-hundred-megabyte log file:
1. The browser pre-registers the transfer metadata (filename, byte size, MIME type) with the Cloudflare Worker to obtain a persistent database entry.
2. The browser streams the payload directly to high-throughput Anycast storage nodes (backed by Tokyo Cloudflare Edge and AWS S3 infrastructure) using chunked multipart streams.
3. **The Worker's memory and CPU consumption remains at 0.00%**, completely circumventing serverless execution limits.

## Real-Time Progress & Dynamic Bandwidth Telemetry

Modern developers demand desktop-grade feedback during heavy file transfers. Traditional `fetch()` APIs provide no granular upload progress hooks.

XPT-Clip utilizes native `XMLHttpRequest.upload.onprogress` with sliding-window bandwidth calculation:

```javascript
xhr.upload.onprogress = (event) => {
  if (event.lengthComputable) {
    const percent = Math.round((event.loaded / event.total) * 100);
    const elapsedSeconds = (Date.now() - startTime) / 1000;
    const currentSpeedMBs = (event.loaded / 1024 / 1024 / elapsedSeconds).toFixed(1);

    progressBar.style.width = `${percent}%`;
    progressLabel.innerText = `${percent}% (${(event.loaded/1024/1024).toFixed(1)}MB / ${(event.total/1024/1024).toFixed(1)}MB - ${currentSpeedMBs} MB/s)`;
  }
};
```

This delivers an interactive, real-time UI that displays exact transferred bytes, remaining percentage, and live upload throughput (`MB/s`).

## Edge Reverse-Stream Proxy: Eliminating Cross-Border Drops

A major pitfall of relying on public storage relays is link degradation:
* Public download URLs often trigger browser security warnings.
* ISP routing inconsistencies on mobile 4G/5G networks frequently cause third-party domain connection drops or TLS handshake timeouts.
* External services obscure the original filename into randomized hashes.

XPT-Clip completely eliminates redirection by turning the Cloudflare Worker into a **Transparent Edge Reverse-Stream Proxy**:

```javascript
// Worker Transparent Streaming Pipe
export async function handleFileDownload(env, clip) {
  const upstreamResponse = await fetch(clip.remote_url, {
    headers: { 'User-Agent': 'XPT-Clip-Proxy/2.0' }
  });

  const headers = new Headers(upstreamResponse.headers);
  // Enforce native original filename preservation
  headers.set('Content-Disposition', `attachment; filename*=UTF-8''${encodeURIComponent(clip.file_name)}`);
  headers.set('Cache-Control', 'public, max-age=3600');

  // Stream raw bytes directly to client via Cloudflare Anycast
  return new Response(upstreamResponse.body, {
    status: upstreamResponse.status,
    headers
  });
}
```

### Why This Matters:
* **Zero Domain Jumping**: The user never leaves your apex domain (`clip.xptdev.com/api/files/:id?download=1`).
* **100% Mobile Reliability**: Cloudflare's local Anycast edge terminates the client connection, preventing packet loss and carrier-level timeouts on mobile devices.
* **Original Filename Retention**: RFC 5987 encoded headers ensure exact filename and extension restoration across macOS, Windows, Linux, Android, and iOS.

## Core Security & Multi-Tenancy Design

A primary flaw of open clipboard tools is that opening registration leads to abuse, while closing it prevents team collaboration. XPT-Clip solves this with a **Two-Tier Dynamic Invite Engine**:

### 1. Zero-Config Super Admin Initialization
On the very first cold run, the database has zero registered users. The first person to visit the platform can claim the **Super Admin** role with a master password. Immediately afterward, registration locks down completely.

### 2. Single-Use Disposable Invite Codes
New users cannot sign up freely. Instead, the Super Admin generates single-use disposable invite codes directly from their dashboard:

```sql
CREATE TABLE IF NOT EXISTS invites (
  id TEXT PRIMARY KEY,
  code TEXT UNIQUE NOT NULL,
  created_by TEXT NOT NULL,
  role TEXT DEFAULT 'user',
  is_used INTEGER DEFAULT 0,
  used_by TEXT,
  created_at INTEGER NOT NULL,
  used_at INTEGER
);
```

When an invite code is submitted during registration, the Worker executes an atomic verification transaction:
1. Confirms the invite code exists and `is_used = 0`.
2. Hashes the new user's password using salted SHA-256 with an edge secret pepper.
3. Inserts the new tenant into `users` and marks `is_used = 1` simultaneously.

### 3. Granular Self-Destruct Timers & Secret Links
Clips feature customizable lifecycle retention policies:
* **10 Minutes (Default)**: Optimal for API tokens, one-time passwords, and sensitive keys.
* **1 Hour / 1 Day / 7 Days / Permanent**.
* **Burn-After-Reading Public Links**: Generate ephemeral links with customizable view limits (e.g., auto-destructs after 1 view) for external sharing without granting account access.

## Deploy Your Own in Under 3 Minutes

The entire codebase is open-source under the permissive **MIT License**. You can deploy it to your own Cloudflare account using the Cloudflare CLI:

```bash
# 1. Clone the repository
git clone https://github.com/x658/xpt-clip.git
cd xpt-clip

# 2. Create your D1 edge database
npx wrangler d1 create clip-db

# 3. Configure wrangler.toml with your database_id
cp wrangler.toml.example wrangler.toml

# 4. Initialize database schema
npx wrangler d1 execute clip-db --remote --file=./schema.sql

# 5. Deploy globally to Cloudflare Workers
npx wrangler deploy
```
