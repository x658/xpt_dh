Among enterprise cloud providers (AWS, Google Cloud, Microsoft Azure), **Oracle Cloud Infrastructure (OCI)** offers what is widely regarded as the most generous permanent free tier in the cloud computing industry:

* **ARM Architecture (Ampere A1)**: Up to **4 OCPUs and 24 GB of physical RAM**.
* **Complimentary Boot Volumes**: **200 GB of high-speed NVMe/SSD block storage**.
* **Generous Egress Bandwidth**: **10 TB per month of outbound internet traffic** with up to 4 Gbps network interfaces.
* **Full KVM Virtualization & Root Access**: Run standard Ubuntu, Debian, or Oracle Linux distributions with native Docker and kernel-level networking.

However, many engineers struggle with initial setup pitfalls—such as unreachable ports caused by dual-layered firewalls, unexpected credit card charges from orphaned boot volumes, or automated instance reclaims due to idle detection.

This guide details OCI's policies, essential anti-billing safeguards, and production-grade Docker deployment patterns.

## 1. Pay As You Go (PAYG) Account Advantages

Standard Free Tier accounts experience severe resource allocation delays ("Out of host capacity") and are subjected to strict **Idle Resource Reclaiming Policies** (instances averaging under 20% CPU, memory, and network throughput over 7 days are automatically stopped or terminated).

The industry-standard approach for serious developers is upgrading the account to **Pay As You Go (PAYG)**:

### Key Advantages of PAYG:
1. **Exemption from Idle Reclamation**:
   * Oracle's official documentation stipulates that idle resource reclamation **only targets unpaid Free Tier accounts**.
   * Upgraded PAYG accounts are permanently exempt; your instances can operate at 0% CPU utilization indefinitely without threat of reclamation.
2. **Strictly \$0.00 While Within Quotas**:
   * OCI meters ARM free usage by core-hours and memory-hours: **3,000 OCPU hours and 18,000 GB hours per month**.
   * For example, running a **2-core, 12GB instance** for an entire 31-day month consumes exactly 1,488 OCPU hours and 8,928 GB hours—precisely **50% of the allowed free quota**—guaranteeing a monthly bill of \$0.00.

## 2. Avoiding Billing Traps: 4 Critical Safeguards ⚠️

When your credit card is linked to a cloud account, avoiding accidental charges requires strict adherence to these four boundaries:

### 1. The Orphaned Boot Volume Pitfall (Most Common)
* **The Rule**: Total block storage across all active instances and detached volumes must **not exceed 200 GB**.
* **The Trap**: When terminating an instance via the web console, Oracle **does not automatically delete the attached boot volume by default**! If you destroy an old instance and spin up a new one, the old disk continues to accrue hourly storage fees in the background.
* **Prevention**: Always select the checkbox: **`Permanently delete the attached boot volume`** whenever terminating instances.

### 2. Idle Reserved Public IPv4 Addresses
* Each active running instance includes 1 ephemeral public IPv4 address at no charge.
* **Prevention**: Do not allocate multiple unattached "Reserved Public IPs" in your Virtual Cloud Network. Unattached reserved IPs may be assessed idle address surcharges.

### 3. Copyright Enforcement & P2P Abuse
* While you receive 10 TB of monthly bandwidth, **never run public BitTorrent or peer-to-peer file sharing on your instances**. Automated DMCA copyright notices frequently result in immediate, non-negotiable account termination.

### 4. Create a \$1 Monthly Budget Alert
In the OCI console, navigate to **Governance & Administration** -> **Budgets**. Create a monthly budget of **\$1.00** with an email alert trigger at **1% (\$0.01)**. This ensures that any misconfigured paid resource immediately triggers an email notification before significant charges accumulate.

## 3. Resolving Network Inaccessibility: Dual Firewalls

New users frequently discover that web servers (such as Nginx on port 80/443) remain unreachable from the public internet even after starting the service. This stems from OCI's **two-tiered security architecture**:

### Step 1: Open Ingress Rules in VCN Security Lists
1. In the OCI Console, navigate to **Virtual Cloud Networks (VCN)** -> select your active subnet -> open **Default Security List**.
2. Click **Add Ingress Rules**.
3. Set Source CIDR to `0.0.0.0/0`, IP Protocol to **All Protocols**, and save.

### Step 2: Clear Host OS iptables Rules
Oracle's default Linux images include restrictive local firewall rules that block incoming traffic regardless of VCN settings. Clear them over SSH:

```bash
# Accept all incoming, forward, and outbound traffic
sudo iptables -P INPUT ACCEPT
sudo iptables -P FORWARD ACCEPT
sudo iptables -P OUTPUT ACCEPT

# Flush existing reject chains
sudo iptables -F

# Persist rules across reboots
sudo netfilter-persistent save
```

### Quick Installation
Execute the official setup script via SSH:

