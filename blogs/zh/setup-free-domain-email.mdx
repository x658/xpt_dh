## 为什么选择 Serverless 架构自建邮箱？

传统自建邮件服务器是公认的“运维噩梦”：
* 需要在 Linux VPS 上手动安装 Postfix、Dovecot、SpamAssassin 等复杂套件；
* VPS 的公网 IP 极大概率早已被各大黑名单库（如 Spamhaus）拉黑，发出的信件 100% 进垃圾箱；
* 必须自行处理证书轮转、防暴力破解与安全补丁。

**Cloudflare 彻底消除了这些复杂性**：
1. **全球 Anycast 边缘网络**：收件由 Cloudflare 全球数百个数据中心就近承接，天然抵御针对邮件端口的分布式拒绝服务（DDoS）攻击。
2. **零服务器维护**：邮件收发全部转为事件驱动函数（Event-driven Workers），不占用任何固定服务器资源。
3. **极高的投递信誉**：依托 Cloudflare 庞大的官方白名单 IP 库，收发信件合规可靠。

## 第一步：配置 DNS 与 MX 路由记录

要让你的域名（例如 `xptdev.com`）能够正常接收发往该域名的邮件，需要在 Cloudflare DNS 管理面板中添加以下官方 MX 解析记录：

| 记录类型 | 主机名 (Name) | 目标服务器 (Mail Server) | 优先级 (Priority) |
| :--- | :--- | :--- | :--- |
| **MX** | `@` | `route1.mx.cloudflare.net` | **10** |
| **MX** | `@` | `route2.mx.cloudflare.net` | **73** |
| **MX** | `@` | `route3.mx.cloudflare.net` | **68** |

在 Cloudflare 控制台的 **Email Routing** 页面点击“一键配置”，系统通常会自动为你写入这些记录。

## 第二步：配置 SPF 与 DKIM 邮箱认证协议

为了确保你发送的邮件不会被 Gmail、Outlook 判定为垃圾邮件甚至直接拦截，合规的 DNS 安全认证记录至关重要：

### 1. 发件人策略框架（SPF - Sender Policy Framework）
添加一条 TXT 记录，声明只有 Cloudflare 的服务器有权代表你的域名投递邮件：
* **类型**：`TXT`
* **主机名**：`@`
* **记录值**：`v=spf1 include:_spf.mx.cloudflare.net ~all`

### 2. 域名密钥识别邮件（DKIM - DomainKeys Identified Mail）
在 Cloudflare 仪表盘中开启 DKIM 签名功能。系统会自动生成一对公私钥，并将公钥以 CNAME 或 TXT 形式发布在你的 DNS 中，对发出的每一封邮件进行密码学数字签名。

## 第三步：部署轻量 Webmail 邮件处理系统

通过部署基于 Cloudflare 的开源邮件系统（例如 Cloud-Mail）：
1. **自动 MIME 解码**：当外部邮件到达时，Worker 触发器启动，利用 `postal-mime` 快速解析出发件人、收件人、标题、HTML 正文与附件。
2. **安全持久化**：正文数据存入免费的 Cloudflare D1（SQLite）中，附件自动归档至 Cloudflare R2 对象存储中，支持高达数千封邮件的免费存储。
3. **优雅的响应式 Web 界面**：无论是在 PC 浏览器还是手机端，都能随时随地登录查看邮件、回复邮件，并轻松创建多个专属二级前缀别名（如 `admin@`、`support@`、`hi@`）。
