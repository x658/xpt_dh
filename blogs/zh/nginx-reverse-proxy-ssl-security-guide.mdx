在构建任何基于 VPS（如甲骨文云、Serv00、DigitalOcean）部署的 Web 体系时，Nginx 作为反向代理网关，承担着流量接入、TLS 加密卸载、限流防刷与动静分离的第一道防线。

然而，许多站长使用的默认配置存在严重缺陷：支持脆弱的陈旧加密套件（如 TLS 1.0/1.1）、缺失关键安全响应头、无频率限制导致接口被轻易刷爆。本文提供一份经过实战检验的 Nginx 工业级生产配置。

---

## 1. SSL Labs A+ 满分 TLS 加固配置

创建 `/etc/nginx/conf.d/security.conf`：

```nginx
# 1. 强制仅支持现代安全协议 TLS 1.2 与 TLS 1.3
ssl_protocols TLSv1.2 TLSv1.3;

# 2. 优化加密套件（前向保密与 AEAD 高强度套件）
ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305:DHE-RSA-AES128-GCM-SHA256:DHE-RSA-AES256-GCM-SHA384;
ssl_prefer_server_ciphers off;

# 3. SSL 会话缓存与 Session Tickets 调优
ssl_session_cache shared:SSL:10m;
ssl_session_timeout 1d;
ssl_session_tickets off;

# 4. 开启 OCSP Stapling (在线证书状态协议装订，提升握手速度 30%)
ssl_stapling on;
ssl_stapling_verify on;
resolver 1.1.1.1 8.8.8.8 valid=300s;
resolver_timeout 5s;

# 5. 生产级安全响应头
add_header X-Frame-Options "SAMEORIGIN" always;
add_header X-XSS-Protection "1; mode=block" always;
add_header X-Content-Type-Options "nosniff" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;

# HSTS 强制全站 HTTPS (建议稳定上线后开启 preload)
add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always;
```

## 2. 速率限制与防 CC 攻击 (Rate Limiting)

防止黑客针对登录、验证码或高耗能 API 发起恶意并发请求：

在 `/etc/nginx/nginx.conf` 的 `http` 块中定义限流区域：

```nginx
# 定义每秒最多 10 次请求的限流区（基于客户端真实 IP）
limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;

# 定义每秒 1 次的严格防刷区（如发送短信/验证码/重置密码）
limit_req_zone $binary_remote_addr zone=strict_limit:10m rate=1r/s;
```

在具体的 `server` 块中应用：

```nginx
server {
    listen 443 ssl http2;
    server_name xptdev.com;

    # 证书文件路径
    ssl_certificate /etc/letsencrypt/live/xptdev.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/xptdev.com/privkey.pem;

    # 包含上述安全参数
    include /etc/nginx/conf.d/security.conf;

    # 敏感接口限流：允许 5 个突发请求 (burst)，超出的立即拒绝
    location /api/auth/ {
        limit_req zone=strict_limit burst=5 nodelay;
        proxy_pass http://127.0.0.1:3000;
        include proxy_params;
    }

    # 主站反代
    location / {
        limit_req zone=api_limit burst=20 nodelay;
        proxy_pass http://127.0.0.1:3000;
        
        # 传递真实客户端 IP
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 3. Certbot 自动化 SSL 证书申请与平滑重载

使用 Let's Encrypt 官方 Certbot 获取免费泛域名或单域名证书：

```bash
# 安装 certbot 及 nginx 插件
sudo apt update && sudo apt install -y certbot python3-certbot-nginx

# 自动配置证书并注入 nginx
sudo certbot --nginx -d xptdev.com -d www.xptdev.com

# 测试自动续期 dry-run
sudo certbot renew --dry-run
```

Certbot 会在系统后台注册 systemd 定时任务，在证书到期前 30 天自动发起续签并热重载 Nginx，完全无需人工干预。

## 4. 总结

通过启用 TLS 1.3、OCSP 装订、严苛的安全响应头以及智能漏桶限流，原本单薄的 VPS 反向代理立刻蜕变成为抵御恶意爬虫与扫描探测的坚固堡垒。
