在多设备（笔记本、台式机、平板与智能手机）之间快速同步文本代码片段、API 凭证、配置文件和临时截图，是每位开发者日常最高频的操作之一。然而，市面上现有的在线剪贴板与文件快传工具普遍存在四大痛点：

1. **隐私泄露风险**：第三方云端剪贴板往往以黑盒方式运行，开发者提交的敏感密钥和代码存在被持久化抓取与审计的安全隐患。
2. **服务器运维成本昂贵**：如果自建传统的 VPS 方案（基于 Docker、Redis、Node.js 或 Nginx），每月需要支付 \$5–\$20 的固定服务器账单，还需要持续打补丁和维护安全组。
3. **Serverless 边缘体积瓶颈**：传统 Serverless 架构（如 Cloudflare Workers 免费层）存在严格的上传限制（100MB 请求体上限、128MB 运行时内存与 10ms CPU 限制），导致无法在大文件传输场景中发挥作用。
4. **公开服务滥用泛滥**：完全匿名的粘贴板极易成为黑客和爬虫垃圾文件的倾倒场，最终导致服务被封或存储爆满。

为了彻底解决以上所有问题，我们设计并开源了 **XPT-Clip** —— 一个完全基于 **Cloudflare Workers** 与 **Cloudflare D1（边缘原生 SQLite）** 运行的轻量级多租户 Serverless 云剪贴板与大文件快传系统。通过独创的 **“智能双引擎分流架构（Smart Dual-Engine）”**，在实现最高 **1GB 超大文件快传** 的同时，达成真正意义上的 **\$0.00 永久免费运行**。

## 整体架构设计（Architecture Blueprint）

XPT-Clip 遵循“去中心化边缘优先”的架构哲学，将控制平面的轻量元数据管理与高通量的数据流传输完全解耦：

```text
[ 开发者多端客户端 (Browser / Mobile) ]
         │
         ├── (≤ 2MB 短文本 / 凭证 / 权限校验) ───► [ Cloudflare Edge Workers ]
         │                                                 │
         │                                                 ▼
         │                                   [ Cloudflare D1 (Edge SQLite) ]
         │                                   ├── 用户鉴权与单次邀请码机制
         │                                   ├── Base64 本地行内数据 (≤ 2MB)
         │                                   └── 剪贴板元数据与分享令牌 (Token)
         │
         └── (> 2MB ~ 1GB 超大文件直接流) ────────► [ 高速边缘分流集群 ]
                                                           ▲
                                                           │ (流式管道传输)
 [ 跨端下载用户 ] ◄── (边缘无感反向代理流) ─── [ Cloudflare Worker Proxy ]
```

### 为什么选择该架构？
* **全球超低冷启动（< 5ms）**：基于 V8 Isolate 隔离沙箱技术，彻底告别传统 Docker 容器几百毫秒甚至数秒的冷启动延迟。
* **智能双引擎混合存储**：轻量数据留在本地边缘 SQLite，百兆大文件彻底绕过 Serverless 内存与执行时间限制。
* **100% 免费额度覆盖**：利用 Cloudflare 每天提供的 100,000 次免费请求、5,000,000 行 D1 读取配额以及零出网流量费（Zero Egress Fees），个人与小团队日常使用完全无需绑定信用卡。

## 1GB 智能双引擎技术突破（Smart Dual-Engine）

边缘计算开发最大的绊脚石就是载荷体积（Payload Limit）。Cloudflare Workers 免费版对请求体有 100MB 刚性限制，且 D1 SQLite 若强行插入数兆的二进制 Base64，会导致数据库查询性能雪崩。

XPT-Clip 设计了**前端智能无感双引擎路由分流机制**：

```text
                         [ 文件拖拽 / 粘贴上传 ]
                                   │
                           判断文件大小 ≤ 2MB ?
                          /                    \
                       [是]                    [否]
                        │                       │
         [ 引擎 1：本地边缘数据库引擎 ]    [ 引擎 2：超大文件高速中继引擎 ]
         • 转换为 Base64 编码            • 预注册文件元数据至 D1
         • 直接存入 D1 SQLite 数据库     • 客户端直接流式分片上传
         • 零外部第三方依赖，极致隐私    • 支持最高 1GB 压缩包/ISO/二进制
```

### 1. 引擎 1：本地边缘引擎（≤ 2MB）
日常复制的 Shell 代码、JSON 日志、`.env` 配置、API Key、文本笔记以及普通截图，直接以 Base64 形式存入 Cloudflare D1。享受最严密的权限隔离保护，毫秒级读取，零外部依赖。

### 2. 引擎 2：高速分流中继引擎（> 2MB 至 1GB）
当需要跨设备传输几十甚至上百兆的代码工程压缩包、设计原稿或系统镜像时：
1. 客户端预先向 Cloudflare Worker 发起元数据注册（文件名、文件大小、MIME 类型），生成持久化索引。
2. 浏览器直接利用分片上传通道，将数据流推送到高性能边缘中继节点。
3. **整个过程中 Cloudflare Worker 的内存占用与 CPU 消耗始终维持在 0.00%**，完美打破了边缘无服务器架构的资源魔咒。

## 实时上传进度与动态带宽遥测（Progress Telemetry）

现代开发者习惯了桌面级软件的交互反馈。传统的 `fetch()` API 无法原生获取上传过程中的精确分片字节进度。

XPT-Clip 采用了原生的 `XMLHttpRequest.upload.onprogress` 事件，并结合滑动时间窗口实时计算传输速率：

```javascript
xhr.upload.onprogress = (event) => {
  if (event.lengthComputable) {
    const percent = Math.round((event.loaded / event.total) * 100);
    const elapsedSeconds = (Date.now() - startTime) / 1000;
    const currentSpeedMBs = (event.loaded / 1024 / 1024 / elapsedSeconds).toFixed(1);

    progressBar.style.width = `${percent}%`;
    progressLabel.innerText = `${percent}% (${(event.loaded/1024/1024).toFixed(1)}MB / ${(event.total/1024/1024).toFixed(1)}MB - ${currentSpeedMBs} MB/s)`;
  }
};
```

不仅能直观看到百分比进度条，还能实时查看当前上传速率（`MB/s`）与已传输字节，带来极致丝滑的桌面级用户体验。

## 边缘无感反向代理流：解决移动端掉线与链接暴露

如果直接给下载用户提供外部第三方的原始下载链接，会面临三大致命缺陷：
* 链接跳转容易触发移动端微信/QQ等内置浏览器的白名单安全拦截。
* 部分运营商 DNS 或移动蜂窝网络对第三方小众域名存在握手缓慢甚至丢包的问题。
* 外部链接往往会把原文件名重命名为随机哈希字符，下载后需要用户手动重命名。

XPT-Clip 将 Cloudflare Worker 打造为**透明边缘反向代理流（Edge Reverse-Stream Proxy）**：

```javascript
// Worker 边缘无感流式传输代理
export async function handleFileDownload(env, clip) {
  const upstreamResponse = await fetch(clip.remote_url, {
    headers: { 'User-Agent': 'XPT-Clip-Proxy/2.0' }
  });

  const headers = new Headers(upstreamResponse.headers);
  // 严格强制遵循 RFC 5987 规范保留原始文件名
  headers.set('Content-Disposition', `attachment; filename*=UTF-8''${encodeURIComponent(clip.file_name)}`);
  headers.set('Cache-Control', 'public, max-age=3600');

  // 直接将上游数据流穿透回传给客户端，不消耗 Worker 临时内存
  return new Response(upstreamResponse.body, {
    status: upstreamResponse.status,
    headers
  });
}
```

* **统一顶级域名**：用户始终在你的自主域名（如 `clip.xptdev.com/api/files/:id?download=1`）完成下载，无任何第三方域名跳出。
* **原生文件名 100% 还原**：通过 `filename*=UTF-8''` 编码协议，在 macOS、Windows、Linux、iOS 和 Android 上均能完整保留中英文字符与文件扩展名。

## 多租户权限与数据安全机制

剪贴板工具如果开放随意注册，容易被滥用；如果写死账号密码，又无法在团队内部安全共享。XPT-Clip 设计了**双层动态单次邀请码机制（Disposable Invite System）**：

1. **首位访问者初始化超级管理员**：全新部署后数据库为空，首位访问系统的用户可自行设定主密码注册为 Super Admin。注册成功后系统立即自动关闭公开注册入口。
2. **一次性邀请码生成**：超级管理员可在后台随时一键生成阅后即焚式单次邀请码（Invite Code）。新成员必须持有有效邀请码才能完成账号注册，注册完成后该邀请码立即作废。
3. **细粒度阅后即焚与有效期设置**：
   * 支持 **10分钟（默认）**、**1小时**、**1天**、**7天** 或 **永久** 有效期。
   * 支持一键生成只读分享链接，并可限定访问次数（如“阅读 1 次后自动销毁”），适用于向外部客户或临时设备发送一次性密码与凭证。

## 3 分钟快速部署指南

XPT-Clip 遵循 **MIT 开源协议**，你可以轻松将其部署到自己的 Cloudflare 账号中：

```bash
# 1. 克隆开源仓库
git clone https://github.com/x658/xpt-clip.git
cd xpt-clip

# 2. 创建 Cloudflare D1 边缘数据库
npx wrangler d1 create clip-db

# 3. 将生成的 database_id 填入 wrangler.toml
cp wrangler.toml.example wrangler.toml

# 4. 初始化数据库表结构
npx wrangler d1 execute clip-db --remote --file=./schema.sql

# 5. 一键发布部署至全球边缘网络
npx wrangler deploy
```
