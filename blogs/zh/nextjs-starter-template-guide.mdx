在构建面向全球开发者的技术平台与工具站点时，国际化（i18n）绝不仅仅是前端字符串字典的简单替换。如果采用纯客户端状态切换语言，不仅会导致首屏渲染闪烁（Hydration Mismatch）、拖慢最大内容绘制（LCP），更会让搜索引擎爬虫无法独立索引各个语种的页面。

本文将从生产环境架构出发，详解如何基于 **Next.js 16 App Router + `next-intl` + 服务端 MDX（RSC）** 构建一套静态预渲染、零客户端多余开销的多语言 Web 架构。

---

## 一、多语言 URL 拓扑设计与前缀策略

在设计多语种路由时，常见的方案有子域名隔离（如 `zh.example.com`）与子路径路由（如 `example.com/zh`）。从域名权重集中度（Domain Authority）和证书维护成本来看，**子路径路由配合 `as-needed` 默认语言省略策略**是工程上的最优解：

* **默认语言（如 `en`）**：直接挂载于根路径（`/`、`/tools`、`/blog`）。
* **扩展语言（如 `zh`、`ja`）**：通过显式语言前缀挂载（`/zh/tools`、`/ja/blog`）。

```typescript
// i18n/routing.ts
import { defineRouting } from 'next-intl/routing';
import { createNavigation } from 'next-intl/navigation';

export const LOCALES = ['en', 'zh', 'ja'] as const;
export type Locale = (typeof LOCALES)[number];
export const DEFAULT_LOCALE: Locale = 'en';

export const routing = defineRouting({
  locales: LOCALES,
  defaultLocale: DEFAULT_LOCALE,
  localePrefix: 'as-needed',
  localeDetection: false, // 关键：禁止对搜索引擎爬虫进行强制 307 语言重定向
});

export const { Link, redirect, usePathname, useRouter } =
  createNavigation(routing);
```

> **核心避坑指南**：务必将 `localeDetection` 设为 `false`。许多团队开启自动语言重定向后，由于 Googlebot 爬虫主要从美国节点发起请求（携带 `Accept-Language: en-US` 或不带语言头），中间件会强制把访问 `/zh/...` 的爬虫 307 重定向回英文首页，直接导致中文和日文页面完全无法被 Google 收录！正确的做法是保持所有语言 URL 可直达，仅在前端用非侵入式提示条引导真人用户切换。

## 二、全量静态预渲染（`generateStaticParams`）

为了让全球边缘节点（CDN Edge）实现 50ms 以内的首字节响应（TTFB），我们需要在构建阶段（Build Time）将所有语种与文章路径组合全部静态化，而非每次请求时动态计算。

在 `app/[locale]/blog/[slug]/page.tsx` 中，通过遍历所有语种与对应的 MDX 文件生成静态参数矩阵：

```typescript
// app/[locale]/blog/[slug]/page.tsx
import { LOCALES, Locale } from '@/i18n/routing';
import { getPosts } from '@/lib/getBlogs';
import { setRequestLocale } from 'next-intl/server';

export async function generateStaticParams() {
  const allParams: { locale: Locale; slug: string }[] = [];

  for (const locale of LOCALES) {
    const { posts } = await getPosts(locale);
    for (const post of posts) {
      allParams.push({
        locale,
        slug: post.slug.replace(/^\//, ''),
      });
    }
  }

  return allParams;
}
```

配合组件顶部的 `setRequestLocale(locale)` 调用，Next.js 16 会在编译期把每一篇多语言文章直接编译为静态 HTML 与 RSC 载荷，彻底消除运行时服务端计算开销。

## 三、双向 `hreflang` 与 Canonical 规范化元数据

多语言站点在搜索引擎中最常见的错误是缺少双向互指的 `hreflang` 标签，导致不同语种的同主题页面被误判为重复内容。在构建 Metadata 时，每个页面必须同时输出自引用的 `canonical` 以及包含 `x-default` 在内的全语种替代链接：

```typescript
// lib/metadata.ts
export function buildAlternates(siteUrl: string, locale: string, defaultLocale: string, canonicalPath: string) {
  const cleanPath = canonicalPath === '/' ? '' : canonicalPath;
  const canonical = `${siteUrl}${locale === defaultLocale ? '' : `/${locale}`}${cleanPath}`;

  const languages: Record<string, string> = {};
  for (const lang of ['en', 'zh', 'ja']) {
    languages[lang] = `${siteUrl}${lang === defaultLocale ? '' : `/${lang}`}${cleanPath}`;
  }
  languages['x-default'] = `${siteUrl}${cleanPath}`;

  return { canonical, languages };
}
```

### 多语言 SEO 校验三原则：
1. **双向对称性**：如果 `/blog/guide` 指向了 `/zh/blog/guide`，那么 `/zh/blog/guide` 的 HTML 头部也必须包含指回 `/blog/guide` 的标签。
2. **使用完整绝对路径**：所有 `canonical` 与 `hreflang` 必须携带 `https://` 协议头与完整主域名。
3. **禁止拦截 `/_next/` 静态资源**：在 `robots.txt` 中切勿封禁 `/_next/`，确保搜索引擎渲染引擎（WRS）能够完整加载样式表与脚本。

## 四、基于 React Server Components 的 MDX 编译流水线

传统的客户端 Markdown 渲染会把数十 KB 的解析器打包进浏览器端 JS。在 Next.js App Router 架构下，我们可以利用 `next-mdx-remote-client/rsc` 在服务端完成语法树解析与 GFM 表格转换：

```tsx
import { MDXRemote } from 'next-mdx-remote-client/rsc';
import remarkGfm from 'remark-gfm';
import MDXComponents from '@/components/mdx/MDXComponents';

export async function ServerArticleBody({ source }: { source: string }) {
  return (
    <article className="prose prose-slate dark:prose-invert max-w-none">
      <MDXRemote
        source={source}
        components={MDXComponents}
        options={{
          parseFrontmatter: true,
          mdxOptions: {
            remarkPlugins: [remarkGfm],
          },
        }}
      />
    </article>
  );
}
```

这种架构让纯文本与代码块完全在构建期转化为轻量 HTML，同时仍允许在文章内部局部嵌入交互式客户端组件（Islands Architecture）。

## 五、总结

通过 **子路径 `as-needed` 路由 + 关闭强制爬虫重定向 + `generateStaticParams` 全量静态化 + 对称式 `hreflang` 元数据 + RSC MDX 编译**，我们可以在一套代码库中同时兼顾极致的 Core Web Vitals 性能指标与多语种搜索引擎友好度。
